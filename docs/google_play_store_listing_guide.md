# 구글 플레이스토어 등록 정보(Store Listing) 최적화 가이드라인

본 가이드라인은 **ASO(App Store Optimization, 앱 스토어 검색 최적화)**를 통한 자연 유입(Organic Search) 극대화와 상세 페이지 방문자의 **설치 전환율(CVR, Conversion Rate)**을 최적화하기 위한 실무 등록 가이드입니다.

---

## 1. 텍스트 메타데이터 최적화 전략

Google Play 알고리즘은 **앱 이름, 간단한 설명, 자세한 설명**의 모든 텍스트를 인덱싱합니다. 자연스러운 문맥 속에 목표 키워드를 전략적으로 배치해야 합니다.

### 1.1 메타데이터 사양 및 작성 기준

| 항목 | 글자 수 제한 | 노출 위치 및 역할 | 작성 전략 및 핵심 원칙 |
| :--- | :--- | :--- | :--- |
| **앱 이름 (Title)** | 최대 **30자** | 검색 결과, 카테고리 랭킹, 상세 최상단 | • **가중치 최상위**: 핵심 검색 키워드 1~2개 반드시 포함<br>• **추천 구조**: `[브랜드명] - [핵심 기능/가치]` 또는 `[핵심 키워드] : [브랜드명]`<br>• 특수문자 남발, 이모지, 대문자 연속 사용 지양 |
| **간단한 설명 (Short Description)** | 최대 **80자** | 앱 상세 페이지 상단 (더보기 클릭 전) | • **전환율의 핵심**: 앱의 핵심 가치 제안(UVP) 한 문장 압축<br>• 사용자가 얻는 혜택(Benefit)과 문제 해결 명시<br>• 2차 타깃 롱테일 키워드 자연스럽게 결합 |
| **자세한 설명 (Full Description)** | 최대 **4,000자** | 상세 페이지 '앱 정보' 전체 영역 | • **인덱싱 & 전환 유도**: 앱 기능, 사용 시나리오, 차별점 상세 설명<br>• **키워드 밀도**: 주요 타깃 키워드별 **2~3%** 밀도 유지<br>• 불릿 포인트(`•`), 명확한 섹션 구분을 통한 모바일 가독성 확보 |

---

### 1.2 섹션별 작성 템플릿 & 실무 팁

#### (1) 앱 이름 (Title - 최대 30자)
* **좋은 예시:**
  * `스픽(Speak) - AI 영어회화 & 발음 튜터` (24자)
  * `토스(Toss) - 쉽고 안전한 금융·송금·투자` (25자)
* **피해야 할 예시:**
  * `최고의 무료 가계부 앱 1등 No.1` (구글 정책 위반 및 검색 품질 저하)

#### (2) 간단한 설명 (Short Description - 최대 80자)
* **구조:** `[타깃 사용자]를 위한 [핵심 기능/해결책]으로 [얻게 되는 궁극적 가치/결과]를 경험하세요.`
* **실무 팁:** 첫 문장에서 사용자가 "이 앱이 나에게 왜 필요한가?"에 대한 답을 즉시 얻을 수 있어야 합니다.

#### (3) 자세한 설명 (Full Description - 최대 4,000자 권장 구조)
```text
[도입부 - Hook & Value Proposition (상단 3~5줄)]
- 앱이 해결하는 일상의 문제점 제시
- 핵심 가치 제안 요약 및 주요 타깃층 명시

[핵심 기능 소개 (3~5개 주요 기능)]
• 기능 1: [기능명] - 구체적인 사용 시나리오와 혜택 설명
• 기능 2: [기능명] - 차별화된 편의성 강조
• 기능 3: [기능명] - 직관적 사용 경험 전달

[이런 분들께 추천합니다 (Target Persona)]
- 바쁜 일상 속에서 간편하게 OO 관리가 필요하신 분
- 기존 OO 서비스의 복잡한 절차에 불편함을 느끼셨던 분

[신뢰도 & 보안 요소]
- 데이터 암호화, 개인정보 보호 정책 준수 명시
- 고객센터 및 지원 채널 안내 (이메일/FAQ 링크)
```

## 2. 시각 및 그래픽 애셋 제작 가이드

시각 요소는 사용자가 앱을 탐색하고 설치 버튼을 누르기까지 걸리는 시간(평균 3~7초) 내에 직관적인 신뢰와 흥미를 유발해야 합니다.

### 2.1 애셋 규격 및 디자인 원칙

```
┌────────────────────────────────────────────────────────────────────────┐
│                        스토어 그래픽 애셋 체크리스트                   │
├───────────────────┬──────────────────────────┬─────────────────────────┤
│ 애셋 종류         │ 규격 및 형식             │ 디자인 핵심 가이드라인  │
├───────────────────┼──────────────────────────┼─────────────────────────┤
│ 앱 아이콘         │ 512 x 512 px (32-bit PNG)│ • 단순하고 명확한 심볼  │
│                   │ 최대 1MB, 투명도 불가    │ • 글자/뱃지/테두리 지양 │
├───────────────────┼──────────────────────────┼─────────────────────────┤
│ 그래픽 이미지     │ 1024 x 500 px (JPG/PNG)  │ • 피처드/프로모션 대표  │
│ (Feature Graphic) │ 24-bit PNG 또는 JPG      │ • 핵심 요소를 중앙 배치 │
├───────────────────┼──────────────────────────┼─────────────────────────┤
│ 스크린샷          │ 최소 4장 ~ 최대 8장 권장  │ • 1~3번에 핵심 기능 배치│
│                   │ 16:9 또는 9:16 (FHD 이상) │ • 상단 1줄 카피 오버레이│
├───────────────────┼──────────────────────────┼─────────────────────────┤
│ 홍보 동영상       │ YouTube URL 링크         │ • 30초~1분, 자막 필수   │
│                   │ (수익화/광고 해제 필수)   │ • 첫 5초 내 핵심 UI 노출 │
└───────────────────┴──────────────────────────┴─────────────────────────┘
```

### 2.2 스크린샷 스토리보드 설계 전략

1. **1번 스크린샷 (가장 강력한 Hook):** 앱의 가장 매력적인 핵심 기능 + 가장 큰 사용자 혜택을 담은 헤드라인 카피.
2. **2번 스크린샷 (핵심 문제 해결):** 사용자가 가장 빈번하게 사용할 주력 기능 및 UI 화면.
3. **3번 스크린샷 (차별화 포인트):** 경쟁사 대비 독보적인 편의 기능 또는 차별점.
4. **4~5번 스크린샷 (부가 기능 및 신뢰성):** 개인화 설정, 통계/리포트, 보안 및 커뮤니티 기능.

## 3. 구글 플레이 정책 및 심사 필수 준수 사항

구글 플레이의 **스토어 등록정보 정책(Metadata Policy)**을 위반할 경우, 앱 심사 거절(Reject) 또는 스토어 등록 정보 강제 리셋/노출 제한 등의 불이익을 받을 수 있습니다.

### 3.1 금지 사항 및 주의사항

* ❌ **순위, 수상, 가격 홍보 문구 금지:**
  * `1위`, `최고의`, `No.1`, `Best`, `무료`, `특가 세일`, `다운로드 100만 돌파` 등의 수식어는 앱 이름, 아이콘, 그래픽 이미지에 사용할 수 없습니다.
* ❌ **키워드 스터핑(Spam) 금지:**
  * 쉼표(`,`)나 해시태그(`#`)를 이용해 관련 키워드를 무의미하게 나열하는 행위는 알고리즘 페널티 대상입니다.
* ❌ **출처 불명 추천사 및 인용구 사용 불가:**
  * "사용자 리뷰: 정말 최고의 앱이에요!" 같은 검증 불가능한 익명 인용문 작성 금지.
* ❌ **타사 브랜드명 및 상표 무단 도용 금지:**
  * 다른 브랜드나 유명 상표, 저작권 캐릭터를 설명이나 그래픽에 무단 포함 불가.

## 4. 카테고리 설정, 현지화 및 지속적 최적화 (A/B 테스트)

### 4.1 카테고리 및 태그(Tags) 설정
* **기본 카테고리:** 앱의 핵심 기능과 가장 일치하는 카테고리 1개 지정.
* **태그(최대 5개):** Google Play Console에서 제공하는 공식 태그 목록 중 앱의 서브 기능/장르와 가장 밀접한 태그 5개를 등록하여 유사 앱 추천 알고리즘 노출을 극대화합니다.

### 4.2 스토어 등록정보 실험 (A/B Testing)
Play Console의 **스토어 등록정보 실험(Store Listing Experiments)** 도구를 활용하여 데이터 기반으로 최적화합니다.
* **테스트 대상:** 앱 아이콘, 피처 그래픽, 스크린샷 순서/카피, 간단한 설명.
* **원칙:** 한 번에 1가지 변수(예: 아이콘 시안 A vs B)만 테스트하여 인과관계를 명확히 규명.
* **의사결정:** 통계적 유의수준(최소 90% 이상)에 도달했을 때 승리 시안 적용.

### 4.3 글로벌 현지화 (Localization)
* 단순 기계 번역을 지양하고, 진출 국가별 검색 행동 및 로컬 키워드 분석을 반영한 맞춤형 번역 적용.
* 국가별 통화, 문화적 맥락, 스크린샷 내 언어 현지화 적용.

## 5. 출시 전 최종 점검 체크리스트

```markdown
- [ ] [Title] 앱 이름이 30자 이내이며 핵심 키워드를 포함하고 있는가?
- [ ] [Short Desc] 간단한 설명(80자 이내)에 앱의 핵심 가치 제안이 명확한가?
- [ ] [Full Desc] 자세한 설명이 읽기 쉬운 구조(불릿 포인트)로 정리되어 있는가?
- [ ] [Policy] '1위', '무료', '최고' 등 금지된 홍보성 문구가 배제되었는가?
- [ ] [Graphic] 아이콘(512x512) 및 피처 그래픽(1024x500) 규격이 정확한가?
- [ ] [Screenshots] 첫 3장의 스크린샷에 가장 강력한 가치가 시각화되어 있는가?
- [ ] [Category & Tag] 적합한 카테고리 1개 및 태그 5개가 설정되었는가?
- [ ] [Contact] 공식 개발자 연락처(이메일, 웹사이트, 개인정보처리방침 URL)가 등록되었는가?
```
