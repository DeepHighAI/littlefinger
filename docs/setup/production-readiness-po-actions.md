4. 앱 인증 화면의 **업데이트 확인(Check for updates)**을 누릅니다.
5. 인증 결과 또는 오류 화면을 보내주세요. 인증 완료 후에도 앱 준비 상태 검토가 별도로 진행되므로

공식 참고: [app-ads.txt를 통한 앱 인증](https://support.google.com/admob/answer/14538460?hl=ko).

## 1. AdMob 유럽 규정 메시지 게시·앱 연결 확인

### 따라 하기

1. [AdMob](https://admob.google.com)에 로그인합니다.
2. **개인 정보 보호 및 메시지 → 유럽 규정 → 관리**로 이동합니다.
   처음 설정하는 경우에는 **만들기**가 표시될 수 있습니다.
3. 기존 메시지가 있다면 먼저 엽니다. 같은 용도로 중복 생성하지 않아도 됩니다.
4. 상태가 **게시됨**인지 확인합니다. **임시 저장**은 게시된 상태가 아닙니다.
5. 메시지의 **앱 선택**에서 리틀핑거 Android 앱이 선택되어 있는지 확인합니다.

   | 확인 항목 | 일치해야 하는 값 |
   |---|---|
   | 앱 | 리틀핑거 Android |
   | AdMob 앱 ID | `ca-app-pub-9625042173735017~2273644771` |
   | Android 패키지 이름 | `com.littlefinger.app` |

   패키지 이름은 앱 설정에서 확인합니다. `~`가 들어간 앱 ID와 `/`가 들어간 광고 단위 ID는 다릅니다.
   메시지에 앱을 선택하는 작업과 AdMob 앱에 Play 스토어 등록정보를 연결하는 작업도 별개입니다.
6. 메시지가 없으면 새로 만들고, 미게시 상태면 기존 메시지를 수정합니다.
   선택된 앱, 지원 언어, 기존에 승인한 개인정보처리방침 URL, 사용자 선택 항목과 대상 지역을 검토합니다.
7. 미리보기로 확인한 뒤 **게시**합니다. 이미 올바르게 게시되어 있다면 변경하지 않아도 됩니다.

법적 문구를 임의로 만들거나, 테스트 동의창을 띄우려고 대상 지역을 **모든 지역**으로 바꾸지 마세요.
정책 판단이 필요한 설정이 불분명하면 해당 화면을 보내주세요.

공식 참고: [앱용 유럽 규정에 따른 메시지 작성](https://support.google.com/admob/answer/10113207?hl=ko).

### 작업 후 보내주실 내용

- 메시지 상태: 게시됨 / 미게시
- 리틀핑거 앱 선택 여부
- 설정된 대상 지역
- 게시한 경우 게시 시각: 한국 시간 기준

한국에서 동의창이 뜨지 않는 것만으로 오류는 아닙니다. 다만 이전 별도 테스트 앱에서는 유럽 지역
테스트 조건에서도 동의창을 받지 못했습니다. 설정 확인 후 개발 측에서 테스트 기기 설정과 설치
앱의 차이를 점검하고 실제 동의창 표시·선택·개인정보 옵션 재열기를 검증합니다.
**게시 확인만으로 문제가 해결됐다고 판단하지 않습니다.**

## 2. 무과금 영구 보관 주문 한 건만 환불·권한 취소

### 먼저 대상 주문 확인하기

**환불은 되돌릴 수 없습니다. 아래 주문 한 건만 처리하세요.**
영구 보관은 정기 결제가 아닌 **일회성 인앱 상품**입니다.

| 확인 항목 | 대상 주문 |
|---|---|
| 앱 / 패키지 | 리틀핑거 / `com.littlefinger.app` |
| 상품 | 약속 영구 보관 / `promise_permanent_access` |
| 구매 시각 | **2026년 9월 5일 21:45경, 한국 시간** / UTC 12:45경 |
| 구매 화면 표시 가격 | ₩2,000 |
| 구매 조건 | 테스트 카드 사용, **청구되지 않는 테스트 주문** |
| 처리 범위 | 이 주문 한 건만 |
| 제외 대상 | 같은 날 **20:46경 슬롯 구매** 및 나머지 모든 주문 |

서버 검증 기록 시각은 `2026-09-05 12:45:18.741689 UTC`입니다.
Play 주문 생성 시각과 초 단위까지 같지 않을 수 있으므로 **시각만으로 고르지 마세요.**
앱·상품·구매 계정·테스트 주문 여부를 함께 확인해야 합니다.

### 따라 하기

1. [Play Console](https://play.google.com/console)에 로그인합니다.
2. 왼쪽 메뉴에서 **주문 관리**를 엽니다.
3. 테스트 구매에 사용한 Google 계정의 전체 이메일 또는 정확한 주문 ID로 검색합니다.
   검색어는 콘솔 안에서만 사용하고, 이메일·전체 주문 ID를 대화에 올리지 마세요.
4. 위 표와 일치하는 주문 상세 화면을 엽니다. 여러 주문을 동시에 선택하지 마세요.
5. **주문 환불 / 환불**을 눌러 확인 화면을 엽니다.
6. **권한 취소 / Revoke entitlement** 옵션이 표시되면 선택합니다.
   부분 환불이나 정기 결제 취소는 선택하지 마세요.
7. 대상 주문, 전액 환불 여부, 권한 취소 선택 여부와 환불 사유를 검토한 뒤 제출합니다.
8. 완료 시각, 최종 주문 상태, 권한 취소 선택 여부를 기록합니다.

**다음 경우에는 제출하지 말고 화면을 보내주세요.**

- 대상 주문을 확실히 구분할 수 없음
- 무과금 테스트 주문인지 확인할 수 없음
- 권한 취소 옵션이 보이지 않음
- 이미 환불된 주문임
- 환불 버튼이 없거나 오류가 발생함

다른 주문으로 대체하거나 확인을 위해 새 유료 주문을 만들지 마세요.
화면을 보낼 때는 구매자 이메일, 전체 주문 ID, 구매 토큰과 인증정보를 가려주세요.

공식 참고: [앱 주문 관리 및 환불 처리](https://support.google.com/googleplay/android-developer/answer/2741495?hl=ko),
[Google Play Billing 테스트](https://developer.android.com/google/play/billing/test?hl=ko).
도움말의 정기 결제용 ‘환불 및 취소’가 이 일회성 상품의 버튼 이름과 같다고 가정하지 마세요.
실제 화면이 다르면 제출 전에 확인합니다.

### 환불 후 앱에서 바로 달라지지 않는다면

개발 측에서 실제 환불 반영 경로, **영구 보관 권한 해제**, 앱 완전 종료 후 재실행 결과와
혜택 중복 지급 여부를 확인해야 합니다. 문서상 정기 확인 작업은 매일 **한국 시간 12:17
(UTC 03:17)** 예정이지만, 즉시 반영을 보장하거나 현재 실행 상태를 확인했다는 뜻은 아닙니다.

**일반 보관 기간이 남아 있으면 영구 보관 환불 후에도 약속을 열람할 수 있습니다.**
이번 작업은 영구 보관 구매 권한을 취소하는 것이지, 약속 기록을 삭제하거나 남은 일반 보관
권한까지 없애는 것이 아닙니다. 데이터베이스를 직접 수정해 환불 성공을 흉내 내지 않습니다.
