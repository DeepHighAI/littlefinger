# 공개테스트 참여자 설문지 — 리틀핑거 0.2.0

Date: 2026-08-31. Play **공개 테스트(open testing)** 참여자에게 돌리는 **Google Forms 설문 본문**이다.
코드펜스 안의 문구는 콘솔에 **그대로 붙여 넣는 값**이고, 표는 손으로 켜고 끄는 설정이다.
출시 절차는 `monetization-retention-release.md`, 등록정보 본문은 `play-store-listing.md`,
내부 결함 목록은 `docs/qa/ADR0015_DEVICE_QA.md`가 각각 맡는다.

PO 확정 (2026-08-31):

| 항목 | 확정값 |
|---|---|
| 산출물 | **이 문서 한 개** — 폼 자동 생성 스크립트는 만들지 않는다 |
| 언어 | **한국어만** (등록정보와 달리 en-US 두 벌을 만들지 않는다) |
| 응답자 식별 | **완전 익명** — 이름·이메일·연락처·후속 인터뷰 항목 없음 |
| 분량 | **16문항 · 약 2분**, 주관식은 선택 1칸뿐 |

수집 목적은 다섯 가지 개선 영역이다: **① UI/UX 디자인 · ② 약속을 주고받을 때의 시스템 ·
③ 추가하고 싶은 기능 · ④ 현실에서 도움이 되게 하는 개선안 · ⑤ 오류 신고.**

두 가지 하드 제약이 모든 문구에 적용된다.

1. **문구 가드 (CLAUDE.md §8-3)** — 설문은 등록정보가 아니지만 테스터에게 보이는 제품 문구이므로
   같은 가드를 적용한다. 사진 첨부는 "증거"가 아니라 **사진**, 확정은 "서명"이 아니라 **승인·확정**,
   기록 지문은 "해시"가 아니라 **기록 지문**이라고 쓴다. 붙여 넣는 블록에서 가드 단어는 0건이다(§5).
2. **판정하지 않는다 (P1)** — 두 사람의 답이 엇갈린 경우를 묻는 문항(Q7)은 **누가 옳았는지 묻지
   않는다.** 그런 선택지도, 그런 문항도 만들지 않는다.

## 1. 폼 설정 (손으로 켜고 끄는 값)

| Google Forms 위치 | 설정값 | 이유 |
|---|---|---|
| 설정 → 응답 → 이메일 주소 수집 | **수집하지 않음** | 완전 익명 확정. 응답에 개인정보가 한 건도 남지 않는다 |
| 설정 → 응답 → 응답 횟수 1회로 제한 | **끔** | 켜면 Google 로그인이 강제되고 계정이 응답에 묶인다 — 익명과 양립하지 않는다 |
| 설정 → 응답 → 응답 수정 허용 | **켬** | 오류 신고 한 줄을 나중에 보태는 경로 |
| 설정 → 프레젠테이션 → 진행률 표시줄 | **켬** | 섹션이 7개다. 2분이라는 안내를 눈으로 확인시켜 준다 |
| 설정 → 프레젠테이션 → 질문 순서 무작위 | **끔** | Q1이 뒤의 모든 답을 갈라 읽는 세그먼트 축이다 |
| 설정 → 기본값 → 기본적으로 필수 질문 | **끔** | 필수는 문항별 §3 표기를 따른다 (Q6·Q15만 선택) |
| 설정 → 퀴즈로 만들기 | **끔** | 정답이 있는 설문이 아니다 |
| 질문 유형 | **파일 업로드는 쓰지 않는다** | 파일 업로드 문항은 Google 로그인을 강제한다. 화면 캡처는 소개글이 안내하는 `task@deephigh.ai` 경로로 받는다 |
| 섹션 | **7개** (§3의 섹션 1~7) | 영역별로 끊어 이탈 지점을 본다 |
| Q10 체크박스 → 응답 확인 | **최대 3개 선택** | 우선순위를 강제해야 순위가 나온다 |

**응답 마감**은 공개테스트 트랙 공개 후 2주로 잡고, 마감 시 "설문 응답 받기"를 끈다.
링크는 Play Console → 테스트 → **공개 테스트 → 의견 URL 또는 이메일 주소** 필드에도 넣는다
(테스터가 스토어에서 바로 들어온다).

## 3. 문항 16개

표기 규칙 — **유형**은 Forms의 질문 유형 이름이고, **필수**는 그 문항의 필수 토글이다.
선택지는 적힌 순서대로 넣는다. `목적`은 콘솔에 넣지 않는 운영자용 메모다.

### 섹션 1. 어떻게 써 보셨나요 (2문항)

섹션 제목과 설명:

```
어떻게 써 보셨나요
답변을 어떻게 읽어야 할지 정하는 두 문항입니다.
```

**Q1. 지금까지 리틀핑거에서 약속을 몇 개 만들거나 참여했나요?**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지: `아직 없어요 (앱만 둘러봤어요)` / `1~2개` / `3~5개` / `6개 이상`
- 목적: 세그먼트 축. 약속 0개 응답자의 평가와 6개 이상 응답자의 평가를 한 표에서 읽지 않는다.

**Q2. 어떤 사람과 약속을 주고받았나요? (모두 선택)**

- 유형: 체크박스 · **필수**
- 선택지: `연인·배우자` / `친구` / `가족` / `직장 동료·업무 관계` / `혼자서 테스트만 해봤어요`
- 목적: ④ 현실 사용 맥락. 등록정보가 겨냥한 커플·친구 가정이 맞는지 본다.

### 섹션 2. 화면과 디자인 (3문항) — ① UI/UX

```
화면과 디자인
보기 편했는지, 어디가 불편했는지만 묻습니다.
```

**Q3. 앱 화면이 보기 좋고 읽기 편했나요?**

- 유형: 선형 척도 `1`~`5` · **필수**
- 라벨: 1 = `많이 불편했어요`, 5 = `아주 편했어요`
- 목적: 디자인 만족 기준선. 빌드 간 비교용 숫자.

**Q4. 보기 불편하거나 헷갈렸던 화면을 모두 골라주세요.**

- 유형: 체크박스 · **필수**
- 선택지: `홈 (진행 중 · 대기 목록)` / `약속 만들기` / `초대 보내기` /
  `상대방이 웹에서 여는 약속 확인 화면` / `약속 상세` / `이행 확인` / `증인 초대` / `알림` /
  `마이 프로필` / `지난 약속` / `불편한 화면은 없었어요`
- 목적: 화면 단위 우선순위. 선택지 문구는 인앱 라벨과 같은 말이다.

**Q5. 디자인에서 가장 먼저 고쳐야 할 것 하나만 골라주세요.**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지:
  - `글자가 작거나 색이 흐려 읽기 힘들다`
  - `버튼이 작거나 어디를 눌러야 할지 모르겠다`
  - `화면 이동 흐름이 헷갈린다`
  - `진행 중·대기·완료 같은 상태 구분이 눈에 안 들어온다`
  - `한 화면에 정보가 너무 많다`
  - `한 화면에 정보가 너무 적어 여러 번 들어가야 한다`
  - `앱 분위기(색·그림·말투)가 약속과 안 어울린다`
  - `고칠 것이 딱히 없다`
- 목적: 문제 **유형** 축. Q4(화면 축)와 교차해 "어느 화면의 무엇"을 뽑는다.

### 섹션 3. 약속을 주고받는 과정 (4문항) — ② 시스템

```
약속을 주고받는 과정
약속을 만들어 보내고, 상대방이 승인해 확정되기까지의 이야기입니다.
아직 보내보지 않았다면 첫 문항은 비워두고 넘어가세요.
```

**Q6. 약속을 보내고 상대방이 승인하기까지 얼마나 매끄러웠나요?**

- 유형: 선형 척도 `1`~`5` · **선택(필수 아님)**
- 라벨: 1 = `많이 막혔어요`, 5 = `아주 매끄러웠어요`
- 목적: 초대 → 승인 동선의 기준선. 안 해본 사람의 낮은 점수가 섞이면 숫자가 망가지므로 필수로 두지 않는다.

**Q7. 약속을 주고받는 동안 막혔던 지점을 모두 골라주세요.**

- 유형: 체크박스 · **필수**
- 선택지:
  - `초대 링크를 상대방에게 보내는 것`
  - `상대방이 링크를 열고도 승인하지 않았다`
  - `로그인 (카카오·구글)`
  - `종료일 정하기`
  - `보상·벌칙 적기`
  - `증인 초대`
  - `확정된 뒤에 내용을 바꾸기`
  - `이행 확인에 답하기`
  - `두 사람의 답이 서로 달랐을 때`
  - `막힌 곳은 없었어요`
- 목적: 상태 전이 단계별 이탈 지점. 아래에서 두 번째 선택지는 **누가 옳았는지 묻지 않는다**(P1).

**Q8. 리마인드 알림(D-7 · D-3 · D-1 · D-Day)은 어땠나요?**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지: `너무 자주 와서 부담스러웠다` / `지금이 적당하다` / `더 자주 왔으면 좋겠다` /
  `알림을 아예 받지 못했다` / `알림을 직접 껐다`
- 목적: 리마인드 오프셋 조정 근거. **`받지 못했다`는 선호가 아니라 결함 신호**다(§4).

**Q9. 상대방이 앱을 설치하지 않고 웹에서 승인하는 방식은 어땠나요?**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지:
  - `이 앱에서 가장 마음에 든 점이었다`
  - `편했다`
  - `있으나 없으나 비슷했다`
  - `상대방이 링크를 의심해서 설명하기 어려웠다`
  - `상대방도 앱을 설치하는 편이 나을 것 같다`
  - `아직 상대방에게 보내보지 않았다`
- 목적: 제품의 최대 차별점 검증. 네 번째 선택지가 많으면 초대 링크의 신뢰 문구를 고친다.

### 섹션 4. 있으면 좋겠는 기능 (1문항) — ③ 추가 기능

```
있으면 좋겠는 기능
최대 3개까지 고를 수 있습니다. 목록에 없으면 마지막 칸에 적어주세요.
```

**Q10. 다음 중 있으면 좋겠는 기능을 최대 3개까지 골라주세요.**

- 유형: 체크박스 · **필수** · **기타 입력 허용** · 응답 확인 = 최대 3개 선택
- 선택지:
  - `매주·매달 반복되는 약속`
  - `자주 쓰는 약속 템플릿`
  - `캘린더 연동`
  - `홈 화면 위젯`
  - `종료일 전 중간 점검(진행 상황 기록)`
  - `세 사람 이상이 함께하는 약속`
  - `벌칙 랜덤 뽑기`
  - `약속 지킴율 배지·기록 모아보기`
  - `약속 검색·필터`
  - `끝난 약속을 다시 약속하기`
  - `약속 기록을 이미지로 내보내기`
  - `기타` (직접 입력)
- 목적: 기능 후보 순위. **`기타` 칸이 주관식 문항을 대체한다** — 별도 서술형 문항을 만들지 않는다.

### 섹션 5. 현실에서의 도움 (2문항) — ④ 개선안

```
현실에서의 도움
앱이 실제로 약속을 지키는 데 쓸모가 있었는지 묻습니다.
```

**Q11. 리틀핑거가 실제로 약속을 지키는 데 도움이 됐나요?**

- 유형: 선형 척도 `1`~`5` · **필수**
- 라벨: 1 = `전혀 도움이 안 됐어요`, 5 = `많이 도움이 됐어요`
- 목적: 제품 효능 기준선. Q3(보기 좋음)과 갈라 본다 — 예쁘지만 쓸모없는 경우를 잡는다.

**Q12. 현실에서 더 도움이 되려면 무엇이 가장 필요할까요?**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지:
  - `상대방도 알림을 확실히 받는 것`
  - `큰 약속을 작게 쪼개 중간에 점검하는 것`
  - `지킨 약속을 남에게 보여주거나 자랑하는 것`
  - `벌칙이 말로만 남지 않고 실제로 굴러가는 것`
  - `카카오톡 안에서 바로 확인하고 답하는 것`
  - `앱을 열지 않아도 알림에서 바로 처리하는 것`
  - `잘 모르겠다`
- 목적: ④ 개선안 방향. 네 번째 선택지의 처리 규칙은 §4에 있다.

### 섹션 6. 오류 신고 (3문항) — ⑤ 버그 리포팅

```
오류 신고
겪은 문제를 고르기만 하면 됩니다. 마지막 한 줄은 선택입니다.
```

**Q13. 앱을 쓰다가 오류·멈춤·이상한 동작을 겪었나요?**

- 유형: 객관식 질문(라디오) · **필수**
- 선택지: `없었어요` / `한 번 있었어요` / `두세 번 있었어요` / `자주 있었어요`
- 목적: 심각도 게이트. 이 분포가 공개테스트 지속 여부의 1차 판단 근거다.

**Q14. 문제가 생긴 곳을 모두 골라주세요.**

- 유형: 체크박스 · **필수** · **기타 입력 허용**
- 선택지:
  - `로그인`
  - `약속 만들기·보내기`
  - `초대 링크 열기`
  - `승인·거절`
  - `사진 첨부`
  - `알림 받기`
  - `광고 보기`
  - `슬롯·보관 구매`

2. **`없었어요`가 다른 항목과 함께 선택된 응답**(Q4 · Q7 · Q14)은 Forms가 막지 못한다.
   집계에서 `없었어요`를 무시하고 나머지 선택만 센다.
3. **Q8의 `알림을 아예 받지 못했다`는 선호가 아니라 결함 신호다.** 조용한 시간(21:00~08:00 KST)에
   눌린 것인지, 기기 토큰이 없는 것인지부터 갈라 본다 — 리마인드 오프셋을 건드릴 근거가 아니다.
4. **Q12의 `벌칙이 말로만 남지 않고 실제로 굴러가는 것`이 1위여도 금전 처리로는 구현하지 않는다.**
   금전 예치와 자동 정산은 영구히 범위 밖이고(CLAUDE.md §8-6), 벌칙은 적어 둔 기록일 뿐이다.
   이 표는 "알림·중간 점검·기록으로 어디까지 대신할 수 있나"로 읽는다.
5. **화면 캡처는 이 설문으로 들어오지 않는다**(파일 업로드 미사용, §1). Q15에 재현 문장이 있고
   캡처가 필요하면, 공지에서 `task@deephigh.ai`를 다시 안내한다.
