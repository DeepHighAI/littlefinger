## Findings

### F1 (major) — Fingerprint third group diverges between confirm screens and detail/history — **FIXED**

`lf_fingerprint(content_hash, version_no)` (canonical, PO-decided format `AAAA-BBBB-NN`) is used
only by `promise_approve`. `20260816000002_promise_detail.sql` and
`20260816202820_f11_amend_agreement.sql` inline their own construction using
`substr(content_hash, 9, 2)` — hash characters, not the version number. Observed live: W03 and the
approve response printed `8060-688F-01`, while SCR-A05 상세 shows `8060-688F-11` for the same v1
record, and `2F6C-834C-A7` for v2 (should be `-02`). The fingerprint printed at confirmation is
supposed to be immutable and re-findable; it can never be matched against the detail screen.
Fix: new migration replacing both inline builds with `public.lf_fingerprint(v.content_hash,
v.version_no)`. **Deployed** as `20260819100000_fix_fingerprint_and_declined_detail.sql` after the
CLI account was fixed; live-verified — `E2E promise A to B` v2 detail now prints `2F6C-834C-02`
(was `2F6C-834C-A7`), third group is the version number everywhere.

### F2 (major) — DECLINED promise detail always returns 500 — **FIXED**

`lf_promise_detail` does `select … into strict` on `promises.current_version_id`, but
`current_version_id` is only ever written by `promise_approve`. A promise declined before any
approval keeps it NULL, the strict select raises NO_DATA_FOUND, and the Edge shell flattens the
unknown message to `E_INTERNAL` (verified live: `promise-detail` → HTTP 500 for the DECLINED
promise; the app shows 약속 상세를 불러오지 못했어요 with a retry that can never succeed). Every
DECLINED (and T-18) card in the 완료 tab is affected. Fix: fall back to the latest
`promise_versions` row when `current_version_id` is null. **Deployed** in the same
`20260819100000` migration; live-verified — the DECLINED promise detail returns HTTP 200 with
version 1 content and fingerprint `735A-1E03-01`.

### F3 (major) — No way to undo a block

SCR-A05 offers 상대방 차단 and it works, but the profile screen has no 차단 목록 관리 section
(spec §10 lists it) and the API contract only defines `user-block` (`blocked: true`) with no
unblock endpoint. A block is currently irreversible from the product. Note: account A blocked
account B during this run and it cannot be lifted without DB access.

### F4 (minor) — Cold-start push tap loses the deep link

With the app process dead (`am kill`), the FCM notification arrives and cold-starts the app, but
tapping it lands on 홈 instead of the promise detail. Warm in-app inbox taps route correctly.
Likely the notification response is consumed before the router is ready. Dev-client caveat: retest
on a release build before treating as confirmed.

### F5 (major UX) — Logout and withdrawal land on the update-required screen — **FIXED**

When the session disappears while on a protected route (마이), the `Stack.Protected` fallback
drops to the first unguarded screen — `update-required` — so both 로그아웃 and 탈퇴 end on
"업데이트 후 이용해 주세요" until the app is relaunched. This is the mirror image of the bug fixed
in `58bcf50` (signed-in users on guest screens); the signed-out direction needs the same routing
rule (`session === null` on a protected path → replace to `/`). **Fixed** in
`apps/mobile/src/app/_layout.tsx` with root-layout tests (auth-callback and `/i/*` app links stay
exempt); ships with the next build — re-verify on device then.

### F6 (minor) — Withdraw warning shows 진행 중 0건 despite an ACTIVE promise

test10 had one ACTIVE promise (approved a minute earlier) and the first withdraw dialog still said
"진행 중인 약속 0건이 있어요". The count that powers the warning (trust-profile snapshot?) lags or
reads the wrong source, which defeats the guard's purpose.

## Environment recipe (Windows quirks that cost time)

- TCP 8081 sits inside a WinNAT excluded port range (8035–8134 this boot) → Metro cannot bind.
  Use `--port 8143`.
- Metro watch mode fails on this machine ("Failed to start watch mode" → transformer broken →
  bundle requests 500). `CI=1` disables watching and works:
  `CI=1 EXPO_NO_TYPESCRIPT_SETUP=1 npx expo start --dev-client --port 8143`
  (`EXPO_NO_TYPESCRIPT_SETUP=1` also dodges a typed-routes crash, `expo-router/_ctx-shared`).
- Launch the dev client with
  `adb reverse tcp:8143 tcp:8143` + deep link
  `littlefinger://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8143`.
- `adb shell input tap` sometimes fails to register on the Fabric surface right after a cold
  bundle load; a 80–100 ms `input swipe x y x y 80` press is reliable. One JS-thread freeze right
  after the first cold load required a dev-menu Reload.
- Emulator clipboard syncs to the host: tap the share sheet's copy icon, then read the invite
  link with PowerShell `Get-Clipboard`.
