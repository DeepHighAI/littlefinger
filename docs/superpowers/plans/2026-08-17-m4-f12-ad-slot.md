# M4 F-12 Home Native Ad Slot Implementation Plan

## Goal

Implement the first M4 shipping unit: the single SCR-A02 native-ad boundary controlled by the
server-owned `app_configs.ads_enabled` flag. The disabled state remains the launch default and must
render no view, placeholder, or reserved spacing.

This unit does not enable production monetization. A production EAS build must receive a real AdMob
Android App ID and native Ad Unit ID through its environment. Local and development builds use
Google's documented test identifiers only. AdMob console privacy messaging and the Play Console
"contains ads" declaration remain release gates.

## Contracts

- `ADS_ENABLED_DEFAULT=false` remains the fail-closed value.
- `app_configs.ads_enabled` is accepted only when its JSON value is the literal boolean `true` or
  `false`. Missing, malformed, or failed reads return the default without blocking SCR-A02.
- Only SCR-A02 imports and renders `LfAdSlot`. No web package imports the ad SDK.
- `LfAdSlot(enabled=false)` returns `null` before consent gathering, SDK initialization, or ad
  creation. This is the code-level no-space guarantee.
- When enabled, Google UMP consent is gathered before SDK initialization. An ad request is made only
  when `canRequestAds` is true. Load/consent failures collapse to no rendered slot and do not affect
  the home list.
- A loaded ad uses `NativeAdView` and registered native assets, includes visible Korean ad
  attribution from a label constant, preserves AdChoices space, and destroys the native object on
  unmount.
- A production native build fails configuration when either AdMob identifier is absent. Development
  builds use Google test identifiers and never request production inventory.

## TDD Sequence

1. Add RED tests for strict flag parsing, missing/error fallback, and the exact `app_configs` query.
2. Add RED component tests proving disabled means no tree and zero consent/SDK/ad calls; enabled
   consent denial/failure also means no tree; a loaded ad renders one slot and cleans up.
3. Add RED SCR-A02 tests proving the flag is loaded once, false/error reserves no space, and true
   appends exactly one slot after list/pagination content.
4. Implement the smallest config reader, native boundary, consent-aware renderer, and home wiring.
5. Install `react-native-google-mobile-ads@16.3.3`, add delayed-measurement Expo configuration, and
   add production environment validation without committing real identifiers.
6. Run focused tests, full tests, typecheck, web build, agent-doc check, Expo dependency check,
   Android production export, and diff checks.

## Follow-up M4 Units

1. J-07 daily ACTIVE metric aggregation and operator review signal; it must never flip
   `ads_enabled` automatically.
2. Full accessibility audit: 48 dp targets, screen-reader roles/names, focus order, text scaling,
   and color-plus-text state communication.
3. The complete §13 acceptance matrix and real-device regression suite.
4. Google Play closed-testing preparation and the 12-testers/14-consecutive-days operational gate.

## Release Gates

- Real Android AdMob App ID and native Ad Unit ID in the EAS production environment.
- AdMob Privacy & Messaging configuration and a verified UMP flow.
- Play Console "Yes, my app contains ads" declaration.
- Production test proving `ads_enabled=false` has no ad view and `true` displays only the SCR-A02
  native slot.
